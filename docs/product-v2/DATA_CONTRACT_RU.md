# PHEISI / PHEISIRAETHA — контракт данных v2

Статус: первый изолированный foundation PR. Направление одобрено владельцем
15 октября 2026 года. Код хранения не подключён к приложению. Настоящий документ
не изменяет старый integration spec, Analysis, Safety или release contracts.

## Область первого PR

Реализуется только `product-v2/storage.mjs`: хранение независимых намерений,
одного черновика на намерение, исходных legacy-документов, конфликтов и квитанций
успешных операций. Нет автоматического запуска, UI, аналитики, оплаты, сети,
синхронизации, удаления или изменений старого localStorage.

Открытие базы происходит только через явный `openStore()`. Обычная загрузка
существующей PWA не импортирует модуль и не выполняет миграцию.

## Версии и владение

- IndexedDB database: `pheisiraetha_business_v2`; database version: `1`.
- Business `schemaVersion`: `2`. Эти две версии имеют разные назначения.
- Имена старых ключей и `APP_VERSION=0.1.0` не меняются.
- `workspaceKey` — локальная идентичность рабочего пространства, не account ID.
- `intentKey` — новый внутренний UUID контейнера. Он не заменяет `intent.id`.
- `draftId` — стабильный UUID одного черновика; keyPath `intentKey` обеспечивает
  максимум один активный черновик на намерение.
- Legacy intention/cycle IDs, в том числе пустые и повторные, сохраняются буквально.

### Хранилища IndexedDB

| Store | Ключ | Содержимое |
|---|---|---|
| `meta` | `key` | Workspace, schema version, revision, selection, baseline pointers |
| `intentions` | `intentKey` | Контейнер намерения с полным `sourceEnvelope` |
| `drafts` | `intentKey` | Один незавершённый observation draft |
| `legacySnapshots` | `snapshotKey` | Неизменяемые исходные JSON-строки и их классификация |
| `operations` | `operationId` | Неизменяемая квитанция успешной команды |

Контейнер намерения хранит `schemaVersion`, `revision`, собственные timestamps,
`sourceSnapshotKey` и весь `sourceEnvelope` прежней формы:

```text
{ version, lang, intent: { id, createdAt, ris, cycles, ...unknown }, ...unknown }
```

Копирование шести RIS-полей вместо полного документа недопустимо. Сохраняются
root/nested unknown fields, собственный ключ `__proto__` как данные, Unicode,
порядок циклов и contradictory revisions. Исходные timestamps отличаются от
времени создания нового контейнера. Прошлые RIS-версии не восстанавливаются.
Числа сохраняются буквально, включая `-0` и parse-accepted переполнение числа
в неизвестных полях (`1e400` становится `Infinity` при JSON.parse). Такие значения
не подменяются на null. Известные числовые поля по-прежнему проверяются историческим
finite/range validator; acceptance unknown fields не усиливается.

Черновик содержит `schemaVersion`, `revision`, `intentKey`, `draftId`,
`basedOnIntentRevision`, `kind: first|progress`, `step`, `values`, `updatedAt`.
Его values могут содержать ещё не выбранные значения и метаданные ответов.
Они никогда не становятся завершёнными циклами сами по себе.

## Команды и ответственность

| API | Назначение |
|---|---|
| `readWorkspace`, `listIntentions`, `readIntention`, `readDraft` | Detached чтение |
| `createIntention` | Добавить новый независимый контейнер |
| `selectIntention` | Изменить selection с проверкой workspace revision |
| `saveDraft` | Записать один draft с проверкой intention/draft revisions |
| `captureLegacyBaseline` | Явно архивировать начальный legacy raw и при возможности перенести его |
| `observeLegacyChange` | Архивировать наблюдённое изменение без замены v2-намерения |
| `importLegacy` | Явный `add-copy` допустимого legacy backup |
| `exportWorkspace` | Согласованный v2 backup всего бизнес-состояния |
| `close` | Закрыть соединение |

Ни одна команда не принимает callbacks для изменения записей и не создаёт
аналитические ответы, синтетические циклы или RIS patches. Generic `replaceAll`,
`clear`, `deleteDatabase` и завершение наблюдения в этом PR отсутствуют.

Store отвечает за структуру хранения и ссылочную целостность. Полноценный domain
builder, правила ответов, RIS edit events и completion commit будут отдельными
этапами; старые completion rules до этого не меняются.

## Атомарность и конкурентность

Каждая mutation выполняет проверки, запись данных, изменение workspace revision
и запись receipt в одной IndexedDB `readwrite` transaction. Успех сообщается
только после `transaction.oncomplete`. Ошибка request, exception, quota failure
или transaction abort означает отсутствие всех изменений этой команды.

JSON-проверка, вычисление fingerprints, UUID и timestamps выполняются до начала
транзакции. Внутри активной транзакции нет ожидания network/crypto/user callbacks.
Проверка `expectedRevision` выполняется внутри той же транзакции, что и запись.

Две вкладки не должны молча перезаписывать один draft. Из двух команд с одной
ожидаемой revision успешно фиксируется максимум одна; другая возвращает
`REVISION_CONFLICT`. Отдельные намерения не меняют данные друг друга.

`operationId` — идентификатор одной логической команды. Повтор с тем же запросом
возвращает сохранённый результат без новых записей. Повтор ID с другим запросом
возвращает `IDEMPOTENCY_CONFLICT`. Fingerprint дополняется проверкой точного
нормализованного запроса; равенство hash не является единственным доказательством.
Повтор старого saveDraft возвращает прежнюю квитанцию, но не откатывает новый draft.

При недоступной IndexedDB нет fallback write в localStorage. Более новая версия
базы или business schema не сбрасывается и не переписывается. `versionchange`
закрывает соединение; blocked upgrade не устраняется удалением данных.

## Миграция и legacy/OFF coexistence

Legacy localStorage является read-only источником. Между ним и IndexedDB нет общей
транзакции; двусторонняя синхронизация не заявляется.

Initial capture разрешён в пустом v2 workspace. Он сохраняет точное значение
`pheisiraetha_v01`, включая null/невалидный JSON. При допустимом legacy backup с
намерением создаётся один контейнер. При `intent:null` или некорректном/неподдержанном
документе рабочее намерение не выдумывается. Исходные bytes остаются в архиве.

Допустимость переноса соответствует историческому import validator, а не его
более permissive loader. Нестандартные сохранённые данные архивируются для
отдельного recovery flow; они не исправляются автоматически.

Обычный импорт файла имеет явный режим `add-copy`. Невалидный импорт возвращает
ошибку без изменения workspace; исходный файл принадлежит вызывающему коду.
Новый operationId означает осознанную новую копию, даже при одинаковом legacy ID.
Автоматического merge/dedup по ID, названию или тексту нет.

После baseline наблюдённые новые legacy bytes архивируются как конфликт. Они
никогда не заменяют v2 данные автоматически. Будущая интеграция должна читать
legacy до и после initial capture, при запуске, событии storage и возвращении
вкладки в фокус. Не наблюдавшиеся промежуточные записи старого приложения
восстановить невозможно; модуль такой гарантии не даёт.

Исторический OFF продолжит читать старый ключ с одним намерением. Новая коллекция
и черновики остаются в отдельной базе и снова доступны совместимой v2-версии.
Старый интерфейс не умеет их отображать. Он может продолжать менять legacy;
изменения потребуют явного разбора конфликта при возвращении в v2.

Запрещены автоматический down-convert всей коллекции в одно намерение,
перезапись старого ключа выбранным намерением и изменение OFF rollback artifacts.

## Backup и ограничения обещаний

V2 export имеет собственный format/schema marker и содержит workspace,
все намерения, черновики и исходные legacy snapshots в согласованном
состоянии одной readonly transaction. Он не выдаётся за backup 0.1.0.
В нём нет результатов аналитики, Safety approvals, entitlements или credentials.
Локальные operation receipts не являются переносимым журналом пользовательских
действий и в export не включаются. Restore обязан создать новые внутренние
идентичности и согласованные связи, не воспроизводить старые команды.

V2 restore, проверка полной резервной копии и remapping внутренних связей —
обязательный отдельный этап до включения нового UI. Экспорт без проверенного
восстановления не считается законченным пользовательским backup workflow.
Текущий `exportWorkspace()` возвращает detached объект, не готовый файл. Обычный
`JSON.stringify` теряет знак `-0` и превращает nonfinite numbers в null; будущий
формат файла обязан иметь явное lossless numeric encoding и round-trip tests.
До этого нельзя подключать API к кнопке «Скачать полную резервную копию».

Успешная transaction защищает от частичных записей; она не отменяет очистку
данных пользователем, ограничения браузера/ОС, потерю диска или eviction.
Будущая PWA должна честно показывать статус последнего сохранения и предлагать
экспорт. Нельзя обещать сохранение ввода, commit которого ещё не завершился.

## Проверяемая приёмка

`product-v2/storage.test.cjs` проверяет настоящий IndexedDB в отдельном браузерном
контексте на localhost, без пользовательского профиля и production service worker.
Проверяются перенос и unknown fields; независимость контейнеров; ID collisions;
CAS; idempotency; reload/restart; offline operations; quota/abort fault injection;
legacy conflicts; отсутствие localStorage writes; future-version protection.

Fault injection quota проверяет обработку искусственно созданного исключения;
это не заявление об измерении реального лимита хранилища конкретного устройства.
Offline storage test не квалифицирует offline app shell, который здесь не меняется.
Foundation пока читает stores целиком для проверки ссылочной/версионной целостности
и сохраняет точный canonical request в receipts. До частого autosave необходимы
измерения объёма и скорости, ограниченный протокол retention технических receipts
и оптимизация чтения без ослабления CAS/idempotency. Это обязательный выходной
критерий PR 2, а не заявление о готовности для неограниченной истории.

Историческая база: `db6920193fb76028947ce148cd8ed61c847c5c3d`.
`product-v2/verify-scope.cjs` проверяет неизменность каждого исходного файла базы и
разрешает только новые файлы этого foundation. Исторические gates сохраняются;
результаты foundation не заменяют release qualification.

Техническая основа транзакций: [Indexed Database API 3.0](https://www.w3.org/TR/IndexedDB/).
